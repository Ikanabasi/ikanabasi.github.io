Making Text-to-SQL Safe to Trust on a Large Schema

I’m building a Text-to-SQL system that can turn a plain-English question into SQL, but the important part of the project is what happens before that SQL is ever allowed near the database.

Overview

The short version of what this project is and why I worked on it.

The first version of the pipeline reads the database schema and foreign keys from PostgreSQL, gives that context to an LLM, and receives generated SQL back. I deliberately stop the pipeline there instead of executing the query automatically.

The work I’m doing now is the safety layer. I’m using SQLGlot to parse generated SQL into an abstract syntax tree, check the query type, validate referenced tables against the real schema, and reject queries that should not be trusted.

The problem

What needed to be solved before thinking about tools or models.

What made it difficult

  • LLMs can generate SQL that looks reasonable but is wrong, unsafe or based on tables that do not exist.
  • A large schema makes simple prompt-only approaches harder to trust.
  • Automatically executing generated SQL would turn a model mistake into a database action.

What I built / designed

  • PostgreSQL schema and foreign-key introspection in Python.
  • LLM prompt flow that uses live schema context.
  • SQL parsing with SQLGlot using the PostgreSQL dialect.
  • Query-type validation and table validation against the known schema.
  • A fail-safe pattern where invalid SQL or a parse error is rejected rather than executed.

How it works

A simplified view of the system or workflow.

User question→PostgreSQL schema→LLM→Generated SQL→SQLGlot safety layer→Approve / reject

Representative validator logic from the current projectPython
from sqlglot import parse_one, expressions
from sqlglot.errors import ParseError

def parse_sql(sql):
    try:
        return parse_one(sql, dialect="postgres")
    except ParseError:
        return None

def validate_tables(parsed, schema_tables):
    tables = [table.name for table in parsed.find_all(expressions.Table)]
    return all(table in schema_tables for table in tables)
